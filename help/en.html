pcMonitor

Version 1.6.0 · Josef Lehner · Linux Mint / GTK 4

Getting started

The left pane lists Linux-detected ports, grouped by type with matching colored icons. Select a port to see its details on the right. The overview button at the top left shows system information, memory and available temperatures.

Visibility and status

The “Show all ports” switch is on the left. When off, it hides only ports confirmed to be empty. Unknown states and errors stay visible. It does not disable hardware or stop detection. Reconnected devices reappear after the next scan. Zero is a valid measured value.

Search filters port names, device descriptions and technical group names. Counts show visible and total ports. Colors identify USB, display, network, audio, drives, PCIe, USB-C and serial ports. Additional symbols and text explain Connected, Empty, Unknown and Error.

Detection and limits

The monitor is read-only. It does not mount drives or change devices. The list reflects the Linux kernel: internal USB ports and USB-2/USB-3 companion ports may differ from physical sockets. A virtual machine shows guest-visible and passed-through hardware. Not all computers report every empty socket. Missing temperature sensors are explicitly shown as unavailable.

Ethernet link is not proof of internet access. Administratively disabled interfaces may have unknown cable status. Audio and serial sockets often lack jack detection. SATA drives are connected even when their filesystems are not mounted.

Settings and menus

File → Quit closes the app. Edit → Settings provides language and refresh interval (2, 3, 5 or 10 seconds). Defaults are German and three seconds. Help → Open help opens HTML documentation; About shows version, author, icon and website; Information lists components and versions. The app follows the system theme and font.

Adding languages

languages/de.json and languages/en.json are UTF-8 JSON objects containing string keys and values only. For example: {"language.name":"Français","ports":"Ports"} in languages/fr.json. New files are discovered when settings opens, without restarting. Missing keys fall back to English. A single valid language is selected automatically. Ten languages are supported. Invalid files report HM103.

Help files are discovered independently as help/<code>.html whenever help is opened. Help opens directly in the configured app language without a separate language dialog. A missing help file reports HM105; it does not switch to English. A help file does not require a matching JSON file.

Local files

Settings: config/settings.json. Error logs: logs/monitor.log with timestamps and up to three rotated files. Icons: resources/. No database is created. Passwords are not saved; device status is not transmitted to the internet.

Commands

Requires Python 3.10+, PyGObject and GTK 4.8+. On Linux Mint: python3, python3-gi and gir1.2-gtk-4.0. Optional: pulseaudio-utils for pactl and pkexec for administrator authorization.

python3 -m monitor
python3 -m monitor --help
python3 -m monitor --version
python3 -m monitor --check
python3 -m monitor --scan
python3 -m monitor --admin

--check validates resources; --scan prints a single JSON snapshot. --admin requests PolicyKit authorization for the read-only hardware helper; the UI, audio and settings remain unprivileged. --admin --scan combines both modes. Exit code 0 indicates success, 1 an error. JSON output may contain hardware identifiers and network addresses.

Administrator mode

The read-only helper accepts only scan and quit over private pipes, never shell commands. It exits when the connection closes. Failed authorization falls back to normal scanning with HM203. Restart admin mode to request authorization again. PolicyKit handles the password prompt. The helper's program files must come from a trusted source.

Starting without DRI3

Since version 1.5.0 the UI defaults to Cairo software rendering. OpenGL and Vulkan are disabled before importing GTK, so rendering does not require DRI3 access. Early launch errors and exit codes are recorded in logs/start.log; desktop launches also display an error dialog when available.

Hardware inventory

Select a hardware category on the left to see all its devices and data on the right: CPU, RAM and installed modules, motherboard, BIOS/UEFI, graphics, NVMe/SSD/HDD, network, USB, displays, PCIe devices, temperatures and serial numbers. Colorful 3D icons identify groups. Searching filters categories and their devices.

Optional tools: sudo apt install pciutils dmidecode smartmontools. Administrator read access adds memory module, firmware and SMART fields where supported. Missing data is explicitly indicated. NVIDIA information is supplemented if nvidia-smi is installed.

EDID shows a preferred mode, not the current resolution. Available RAM includes reclaimable caches. VRAM means dedicated video memory only. Serial numbers and UUID are collected in their own view.

SMART queries are read-only and start no self-tests. Results are cached for 60 seconds; RAM modules for five minutes; NVIDIA values for 30 seconds. External queries have a two-second individual and six-second total budget per scan; deferred queries follow on the next scan. HM204: Additional hardware query failed; basic data remains visible.

Printing and CSV

Above the data panel choose Selected category or All hardware data. Print opens the GTK print dialog; Save CSV opens a destination chooser. Both include complete data for the chosen scope, including devices hidden by search or the empty-port filter. The snapshot is frozen when clicked. CSV uses UTF-8 with BOM, semicolons, sizes in bytes and spreadsheet formula protection.

HM301: CSV could not be saved; check destination and write permissions and retry. HM302: Printing failed; check the printer and python3-cairo / python3-gi-cairo system packages. Cancelling produces no output.

File contains only Quit; Edit only Settings, without blank rows. The left panel starts at its required minimum width.

Menu, refresh and notices

The Hardware menu directly selects any category. Edit → Settings offers Off – manual refresh only. The initial scan and Refresh button remain available; an already running scan may finish.

Notices outside the framed output remain stable while their content is unchanged. Missing permission for DMI UUID or serial numbers (HM201) is not a refresh failure. These fields are retried on manual refresh or restart; use administrator mode for additional permissions.

Diagnostic notes HM401–HM405

Select an affected category from the overview. Notes appear next to the device and are included in CSV and print.

  • HM401: Helper missing. Install the displayed Linux Mint package and refresh. For NVIDIA, first match the driver in Driver Manager.
  • HM402: No bound driver. Check device ID and support. This does not prove a missing package or module; reserved devices and USB userspace interfaces may be normal. Built-in drivers are recognized.
  • HM403: Read permissions missing. Start in administrator mode; installing packages does not grant permissions.
  • HM404: Hardware, firmware or VM does not supply this field. Check the connection or VM support. No blanket installation advice.
  • HM405: Tool installed, but query returned no usable data. Check messages, standby, permissions, service and device support, then refresh.

These notes never install software or load modules. Binding checks cover PCI endpoints and USB interfaces; they are not a complete module compatibility assessment.

Additional data in 1.5.0

GPU: NVIDIA driver, VBIOS, GPU utilization, VRAM usage and memory activity, fan percentage, power, limits, clocks and current/maximum PCIe link. Fan percentage is not measured RPM. Dynamic values are queried on each refresh; unsupported fields remain unavailable.

Network: IPv4/IPv6 prefixes, per-interface default gateways and metrics, Ethernet link modes and Wi-Fi via iw. Logical interfaces are labelled. Bluetooth adapters appear under Network. Missing Wi-Fi drivers may appear under PCIe. NVMe controller data requires nvme-cli and may require administrator read access.

CPU includes SMT state, BIOS Secure Boot, and Mainboard TPM. Kernel sensors supply fan RPM, voltages and power. Unlabelled voltage channels are never guessed to be 12/5/3.3 V rails. Missing sensors do not imply missing lm-sensors. No automatic installation or hardware changes are performed.

HM405 also covers unavailable NVIDIA/NVMe queries. Static controller data may be cached for five minutes. All additional fields are included in CSV and printing.

Language and help packs (1.6.0)

Edit → Settings → Install language and help. Every installation includes a UTF-8 JSON language file and matching HTML help. Installation takes effect immediately, even if the settings dialog is subsequently cancelled. Select the desired interface language above and save.

Local: Select a file such as fr.json, with fr.html beside it. Alternatively use adjacent languages/fr.json and help/fr.html folders. JSON must contain only text keys and values, including language.name. Missing translations fall back to English. English updates must retain all previous keys.

Online: Enter a GitHub repository or HTTPS language server and search for available languages. Repository links use the main branch. Use https://github.com/NAME/REPO/tree/BRANCH or a raw.githubusercontent.com address for another branch. The selected directory must contain manifest.json. The default repository is https://github.com/Franz-Dariwudel/pcMonitor; there is no automatic network access. Select a language to download and validate both files. The list shows language/help versions and local language status. Updates are installed manually.

German and English are included. Additional codes such as es, fr, pt, zh, hi, ar, ru and tr are supported when complete packs are available; no empty placeholders are provided. Help files are detected independently and opened only in the selected language.

Maximum 2 MiB per file; HTTPS without redirects and SHA256 checksums for both downloads. Help must be a complete passive HTML document: text, headings, tables and links are allowed; scripts, forms, embeds and external CSS resources are rejected. Use trusted providers: a checksum in the same manifest is not an independent signature. Both files are validated before replacement. Write errors trigger rollback, but a power failure between the two file renames cannot be completely covered.
